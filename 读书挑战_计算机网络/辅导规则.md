# 计算机网络辅导规则

沿用计组与数据结构项目的中文解释、完整示范、逐步撤除提示及间隔检验方式。当前起点和下一步见[状态与下一步](状态与下一步.md)。

## 教学节奏

1. 新模块先用1～2个短问题检查必要基础，重点是单位换算、二进制/前缀、发送与传播、主机/链路/路由器。没有记录不能推断用户完全没学过。
2. 先讲清“谁向谁发送什么、经过哪里、遵守什么规则”，再给术语和公式。用拓扑图、封装层次、时间线和窗口表展开完整示例，不只给几行定义便连续催答。
3. 给消化空间。必要时完整示范一题，再让用户补关键步骤，最后无提示完成另一道；已经独立会做的部分及时压缩讲解。
4. 一次解决一个明确知识块。综合题按地址、转发、时序或状态等子技能定位卡点，最后回到完整题。
5. 反馈具体正确步骤、错误位置与检验方式，不把遗忘或疑问归因于态度。局部通过不能代表整题或整章掌握。

## 出题与来源

- 出真题前打开[原页](真题/README.md)，核对年份、教材题号、题型、完整题干、选项、拓扑、表格和跨页小问。索引和OCR只帮助定位，不替代原件。
- 引用使用“年份 / 小节 / 题型 / 教材题号 / 原件路径”。教材解析不称官方标准答案，原页中相邻的普通练习不称真题。
- 缺件先回查[完整教材](../books/2026计算机网络_带书签.pdf)；仍不清楚或缺少必要解析时，请用户截图保存到`真题/Chapter章_节/补充原件/`，写清题目与路径，核对后再做。
- 独立推导但未核对解析时明确注明；题目依赖缺失图表或特殊说明时不能猜。自编练习必须标注，且只针对已观察到的卡点或已核对真题的具体一步。

## 条件必须写清

| 题型 | 先核对什么 |
|---|---|
| 时延与吞吐 | bit/Byte、十进制速率与容量口径、链路数、发送/传播时延、首部开销、是否存储转发、排队处理是否忽略 |
| 物理层计算 | Hz与bit/s、码元速率与比特率、信噪比是线性值还是dB、信道模型 |
| ARQ与滑动窗口 | 序号位数、发送/接收窗口、ACK确认约定、是否出错、ACK发送时延与超时模型 |
| Ethernet与无线 | 共享/交换、半双工/全双工、是否使用CSMA/CD或CSMA/CA、帧长是否含首部/填充 |
| IP与路由 | 前缀长度、接口地址、MTU、首部长度、分片偏移单位、路由匹配优先级、ARP缓存和NAT条件 |
| TCP | 字节序号、SYN/FIN占号、ACK含义、MSS、cwnd/rwnd、已发送未确认量、拥塞算法与事件类型 |
| 应用时序 | DNS缓存/递归或迭代、连接是否已建立、HTTP版本/连接复用/流水线、是否忽略传输与处理时间 |

协议或实现有多个版本时，以原题和教材模型为先，不把该模型当作所有实际网络实现的通则。答案有冲突时核对教材及必要的协议原始资料，保留适用条件与待核实部分。

## 掌握证据

| 状态 | 必要证据 |
|---|---|
| 未验证 | 仅阅读、听讲、看示范或自报理解 |
| 提示后完成 | 在提示、纠错或刚看同题答案后完成，记明提示位置 |
| 当场独立通过 | 同时段无提示完成新题或解释，给出关键依据 |
| 间隔独立通过 | 后续时段无提示完成，记实际间隔及原题/新题 |
| 迁移通过 | 无提示处理变换表达、条件或组合方式的题，仅换数字不自动算迁移 |

首次独立正确率单列，记录首次答案、得分及分母。示范、提示后改答、刚纠正后的重做不计首次独立正确；一次正确不直接销账。成绩评价依据来源核对过的测验，并记录是否见过、提示和实际用时。

## 复习与收尾

每天抽1～2个真实卡点，可先按+1、+3、+7天约定复验，再按表现调整；不要清空全部欠题才推进主线。旧Anki由用户自行复习，新卡通常0～3张，允许0张，本地CSV不代表已同步。

每次结束更新日志、错题与当前状态，排程变更只维护[唯一日历](学习排程.md)。记原件、首次表现、提示程度、实际验证、未完成与下次任务。未知用时和原因不猜；没有记录写“无记录”，不能写“没有学习”。文件整理、建立题库和制定计划均不增加学习次数。
